# API contracts

Full interactive docs: run the server and visit `/docs` (Swagger UI,
auto-generated by FastAPI from the Pydantic schemas in
`app/schemas/api.py` — confirmed serving correctly in development).

## Conversation lifecycle

```
POST /v1/conversations
  { "customer_ref": "acct_001" }
  -> { "conversation_id": "...", "session_token": "..." }

POST /v1/conversations/{id}/messages
  Header: Authorization: Bearer <session_token>
  { "message": "please waive my late fee" }
  -> { "status": "awaiting_confirmation" | "awaiting_human_review" | "resolved" | "escalated",
       "intent": "fee_reversal", "decision": {...}, "interrupt_payload": {...} | null }

POST /v1/conversations/{id}/resume
  Header: Authorization: Bearer <session_token>   (only required for kind="confirm")
  { "kind": "confirm", "confirmed": true }
  -- or, from the internal agent console (separate authz, §10.4) --
  { "kind": "human_decision", "outcome": "approved", "agent_id": "agent_42", "note": "..." }
  -> same shape as /messages

GET /v1/audit/{session_id}
  -> { "session_id": "...", "chain_intact": true, "events": [...] }
```

## Status field meanings

| status | meaning | what the frontend should show |
|---|---|---|
| `awaiting_confirmation` | Policy approved; needs the customer's explicit click (§15) | ConfirmActionModal |
| `awaiting_human_review` | Policy engine returned `manual_review`; graph is paused via `interrupt()` | EscalationBanner ("connected to a specialist") |
| `resolved` | Turn is complete — executed, denied, or the customer cancelled | Ledger entry with final status |
| `escalated` | Something else routed to a human (ambiguity exhausted, backend failure, missing entities) | EscalationBanner |

## Error responses

- `401` — missing/invalid session token, or the token doesn't match the
  conversation it's being used against.
- `404` — conversation or audit trail not found.
- `409` — `/resume` called on a conversation that isn't currently paused.

All of the above are exercised by `tests/integration/test_api.py`.
